# 操作说明与异常处理

## 1. 新任务准备

将输入图像、相机标定和模型资源放在工作数据目录。复制示例配置到 `.local/`，填写实际路径和检查过的模型 SHA-256。该目录已在 Git 忽略规则中，避免本机路径和运行资源混入公开仓库。

为每张图像指定不同帧 ID。左右相机分别绑定各自标定。若来自视频，可使用 sample 命令分别抽帧；合并清单后仍然是单张图像处理，不把相似采样时刻视为严格同步。

## 2. 检查与启动

在仓库根目录运行 `python3 -m egosmplx_pipeline check --config .local/pipeline.json`。路径检查通过后执行同样配置的 run 命令。默认运行 1800 次刚体更新和 1600 次身体姿态更新，另保留初始状态候选；随后执行 500+400 步腕点拟合、两组各 400 步轮廓候选与局部谐波连接。流程以指定 session_hand6 结果包为准，详见 REFERENCE_PIPELINE_zh.md。

控制器在输出目录写日志和进度；不通过 shell 拼接执行路径。各模型使用单独 Python 进程，以避免不同版本 PyTorch、MMDetection 和模型注册器相互影响。

## 3. 结果查看

查看 contact_sheet.jpg 对比原始网格、身体校正网格和融合网格。index.html 为离线静态页面，应与同目录对比 JPG 一起复制。逐帧 skeleton.jpg 中的手部骨架来自实际网格回归。

进一步检查 fused/silhouette_targets.json 判断每侧轮廓约束是否启用；不能把因遮挡而跳过的轮廓当作已满足。查看 refinement_report.json 中的深度、腕点距离、姿态增量和优化历史。

## 4. 验收含义

validation.json 记录参数重载、融合重建、OBJ 一致性、手部匹配数量和目标点误差。几何重载绝对误差阈值为 1e-5 米；姿态优化另检查投影重载误差。

缝合检查 MANO 内部和腕部连接边是否具有两片相反方向的相邻三角形，基线腕边界是否保持，以及最终局部表面候选的边长、面积、法向、半径和深度是否满足限制。这不等于整个网格无自交，也不保证手腕外观自然。

## 5. 常见异常

找不到模型或解释器：检查配置字段及外部后端部署。源码仓库不附带模型权重，不能通过跳过检查替代安装。

图像与标定尺寸不同：使用原始分辨率图像，或正确重新标定/转换相机参数；不要只把 JSON 中 size 改成新尺寸。

自动目标不足或分布近似共线：记录失败，检查原图和 Sapiens2 自动预测。程序不自动切换到人工点，也不伪造缺失点。

没有可行身体候选：身体深度或腕距约束无法满足时停止该任务，保留日志。不能为了输出一张图而静默取消约束。

手部未匹配：保留该侧原 SMPL-X 网格，在报告中记录缺失。两侧不能占用同一个 WiLoR 检测结果。没有任何匹配手时跳过腕点与局部表面优化，并明确记录。

目标手部射线位于相机背后或拓扑不兼容：拒绝该帧融合并保留日志，不把无效几何投影到前景。

输出目录已经存在：改用新目录，或在配置、源码和输入没有改变时使用 --resume。续跑通过哈希检查后才复用已完成结果；失败目录保留为 incomplete 版本。

进程被中断：当前任务是前台执行。停止后查看日志与 run_state.json，再决定使用 --resume；仓库没有常驻后台任务控制界面。
